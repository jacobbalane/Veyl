# Development

Veyl's M0 foundation includes runnable desktop and Android interfaces, a three-page website,
portable filter and test-sound code, and build workflows. M1 adds the Rust/Kotlin protocol core and
shared byte vectors. M2 implements Android capture/player flows; M3 adds secure app connections,
protected pairing stores and transport-level diagnostics. Sensing and actions come later.
See [progress](progress.md) for verification and the maintainer steps.

## Prerequisites

Node.js 24+ and Git support the website and desktop UI. Windows native builds also need Rust
stable with rustfmt and clippy, Visual Studio C++ Build Tools with the Windows SDK, and WebView2.
Android builds need a compatible JDK, Android SDK, and the committed Gradle wrapper.

Ask the maintainer before installing system-wide tools unless the session already authorizes
them. The maintainer approved the local toolchain setup on 2026-10-21. Node 26, Rust stable,
Visual Studio 2022 C++ Build Tools, Java 17 and the Android command-line SDK are installed.

Android uses Gradle 9.8.2 (the wrapper checks its SHA-256), Android Gradle Plugin 9.4.1, Kotlin
2.4.21 and SDK 37.2. Java and Kotlin target 17; minSdk remains 26. AGP supplies Kotlin support in
`:app`; only `:core` applies the JVM Kotlin plugin. No Android Studio installation is required.

Set `ANDROID_HOME` to your SDK directory, or put `sdk.dir=C:/path/to/Android/Sdk` in the ignored
`android/local.properties`. The current command-line tools also expose `android sdk install`;
their package paths use slashes, for example `platforms/android-37.2` and `build-tools/36.0.0`.
The older `sdkmanager` interface is deprecated in those tools.

## Commands

Run at the repository root unless a command changes directory.

```powershell
npm ci
npm run format:check
node --test "scripts/*.test.mjs"
node scripts/check-version.mjs
npm run -w desktop dev
npm run -w desktop typecheck
npm run -w desktop test
npm run -w desktop build
npm run -w site dev
npm run -w site build
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace --exclude veyl-desktop
cargo test -p veyl-desktop
cargo test -p veyl-link
cargo run -q -p veyl-link --example gen_vectors
npm run -w desktop desktop
npm run -w desktop package
```

```powershell
Set-Location android
.\gradlew :core:test :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
```

In a browser, `npm run -w desktop dev` shows sample data from `desktop/src/preview/fake-native.ts`:
it connects, starts the engine and then shows a hovering hand with a poke every 3 s. For
screenshots, address options pick a state from the start, for example `?state=aligning`,
`?suspended=sound`, `?warning=drift`, `?tip=volume_low`, `?score=40`, `?mode=pc`,
`?connection=reconnecting` or `?hand=none`; they combine with `&`. Screens open with
`?tab=phones|settings|help`, `?dialog=poke-test`, `?onboarding` or `?onboarding=<step>` (`choose`,
`phone-app`, `pair`, `place`, `phone-play`, `pc-devices`, `pc-play`, `practice`, `actions`; the
`pc-` steps pick PC mode), and `?actions=on` or `?actions=blocked` (Windows blocks the click).
Settings, the actions switch and the poke test work on sample data in memory until a reload.

Use a Visual Studio Developer PowerShell if the MSVC linker is missing. Git's `link.exe` is not
the Microsoft linker. Linux CI tests the portable crates without compiling the Tauri app.
DSP scenario tests run in release mode once M4 supplies the scenarios.

Protocol changes update Rust, Kotlin, [the wire specification](protocol.md) and the generated
`protocol/test-vectors/v1.json` together. The Rust test compares generated bytes with that file;
Kotlin reads it directly as a test resource and reproduces each byte. Generator output is UTF-8
without a BOM. PowerShell 5's `>` uses UTF-16, so use a UTF-8 writer there or regenerate in CI.
The Kotlin protocol sources use ktfmt 0.65's `--kotlinlang-style` (four spaces); Android lint and
core JVM tests check the build. The formatter is a local tool, not an app dependency.

Rust's desktop event test compares its payloads with `desktop/src/api/fixtures/*.json`; TypeScript
tests assign those fixtures to the corresponding API types. After an intentional API change,
regenerate them with `VEYL_UPDATE_FIXTURES=1 cargo test -p veyl-desktop --lib
events::fixtures::rust_payloads_match_committed_interface_fixtures` (set/remove that variable around
the command in PowerShell), then format the JSON with `npx prettier --write desktop/src/api/fixtures`.
Normal tests compare JSON values without rewriting fixtures. Comparison codes in these
examples are fixed test data; copied runtime diagnostics always remove the live code.

The Windows host uses system DNS-SD and connects out; manual host/IPv4 plus port entry works when
discovery is blocked. Pairings use current-user DPAPI and are bound to both identities. The engine
worker currently measures levels through a bounded queue; it does not yet detect a hand or poke.

`cargo run -p veyl-desktop --example audio_devices` reads Windows endpoint metadata and the mode
recommendation without starting capture or changing the Windows defaults. M3P's monitor runs COM
on its own thread and coalesces endpoint/default notifications. IDs stay opaque and case-sensitive;
unknown bus or capability properties use conservative fallbacks. PC capture and its settings are
the next M3P tasks.

M3P's capture backend now owns WASAPI on two capture threads, normalizes PCM/float formats,
downmixes channels, uses Rubato sinc resampling when needed, and filters at 8 kHz before any
consumer sees audio. Raw buffers are never saved: the conversion queue holds about twenty
milliseconds, and the shared queue holds up to two seconds of filtered ten-millisecond PCM blocks.
QPC timestamps use the API's 100 ns units; invalid timestamps stay unknown. Discontinuities reset
history and retain frame gaps. Unit tests use a fake backend and do not open real capture devices.
Production source selection and device pickers follow in M3P.3; native acoustic tests remain pending.

`cargo run -p veyl-lab -- scenarios` distinguishes available scenarios from M4's planned scenes.
The M3 fake phone renders forty seconds of `poke_basic` with real delayed acoustic paths, filtered
16-bit PCM, ten truth pokes and two streams of 4,000 ten-millisecond blocks. It does not yet run the
echo engine or judge gesture detections.

```sh
cargo run --release -p veyl-lab -- fake-phone --scenario poke_basic --realtime
# Or replay an explicitly selected, filtered test recording:
cargo run --release -p veyl-lab -- fake-phone --recording PATH --realtime
```

Open the desktop's Phones tab, use Add by address with `127.0.0.1:47820`, then pair and compare the
code with the simulator's interactive terminal. The simulated phone confirms its own side. It
listens only on loopback; pairings exist only in memory and change when it restarts. Codes are not
printed when output is redirected. Ctrl+C closes the listener and active connection. Omit
`--realtime` to send as fast as the connection allows. `--seed N` chooses a nonzero scenario seed;
`--port N` changes the listening port. Replays retain frame offsets, sequence gaps, raw level
metadata and unknown timestamps, rebasing known capture times to the simulator's current clock.
Reported battery, volume and CPU values are simulated constants. No input audio is played or saved.

`cargo test --release -p veyl-lab` runs the portable end-to-end pairing/session/stream test as well
as replay and pacing checks. The rest of the scenario catalogue and echo analysis follow in M4.

On a connected, listening source, **Record a test** in Live or Help → Diagnostics asks for 30,
60 or 120 seconds and optional Space marks. The banner remains visible until recording stops.
Space marks require focus in Veyl and do not intercept typing, controls or repeated key events.
Files stay in the app data directory's `recordings` folder. Help lists them with Open folder and
confirmed Delete; startup removes dated Veyl folders older than `keep_recordings_days` (seven by
default; zero disables retention). No audio is saved before consent. A separate bounded worker
writes filtered PCM, marks and block metadata, stopping on write failure, overflow, a capture
change or disconnection. WAV gaps are zero-filled and JSONL retains only blocks actually received.
An extra `recording` field in `meta.json` holds status for listing and interrupted-recording
feedback; the shared reader ignores it. M3's `events.jsonl` is empty until the engine emits events.

```sh
cargo run --release -p veyl-lab -- analyze PATH --out ANALYSIS_PATH
```

Analysis retains stream counts, frame/sequence gaps, overlaps, pre-filter level means, filtered RMS
and timestamp availability alongside engine, gesture and meter measurements. It writes the full
JSON/CSV report and motion PNG, preserving existing reports. It reads only the selected local
recording and creates no audio copy. See [offline analysis](lab.md) for profiles and sweeps.

Generate the shared brand assets with `node scripts/render-icons.mjs`. It uses the committed
Manrope source font, creates an outlined ExtraBold wordmark, renders the icons, and copies font
licenses into each app's resources. Run `npm run format` afterwards if the master SVG changed.

The native desktop app starts hidden and opens on `ui_ready`. Closing its window keeps it in the
tray; choose **Quit Veyl** to exit. `--hidden` keeps it in the tray at launch. For isolated debug
checks, set `VEYL_DATA_DIR` to an ignored folder before launching the debug executable. Release
builds always use the standard app data directory. Settings persist a random PC identity and
retain unknown fields. Logging contains lifecycle messages only.

Release signing on Android reads `VEYL_KEYSTORE_PATH`, `VEYL_KEYSTORE_PASSWORD`, `VEYL_KEY_ALIAS`
and `VEYL_KEY_PASSWORD`. Without them, local release builds are unsigned. Debug APKs use the
standard Android debug key. Permanent release-key setup requires the maintainer's explicit
instruction. On this machine the key is configured; see [release.md](release.md) for backup steps.

If the environment blocks Node's test worker processes with `spawn EPERM`, run
`node --test --test-isolation=none "scripts/*.test.mjs"` to exercise the same tests in one process. This does
not establish that the normal CI command passes. Keep that verification pending.

## Versions and release notes

`node scripts/check-version.mjs` checks every version source and Android's integer versionCode.
It also checks workspace versions in an npm lockfile when one exists. A tag build requires the
exact matching tag and nonempty release notes in `CHANGELOG.md`.

`node scripts/bump-version.mjs X.Y.Z` validates every source before updating it, then tries to
refresh both lockfiles without a command shell. A missing tool or failed refresh produces exit
code 1 and prints the commands still needed. Source versions remain updated, so inspect the
changes and finish dependency resolution before committing. Minor and patch must be below 100;
prerelease versions and Android versionCodes outside 1–2100000000 are rejected.

`node scripts/changelog-section.mjs X.Y.Z` prints exactly one release's notes, preserving Markdown.
Missing, empty or duplicate sections fail. No version command creates a tag or release.

## Layout

- `desktop/`: React interface and Windows Tauri host.
- `android/`: Kotlin JVM core and Android application.
- `crates/`: portable DSP, Veyl Link, simulator and lab CLI.
- `site/`: home, docs and changelog for GitHub Pages.
- `protocol/test-vectors/`: shared wire examples, added in M1.
- `assets/brand/`: editable brand sources and generated icons.
- `scripts/`: versions, release notes and icon generation.
- `docs/`: user and contributor docs, decisions and progress.
- `lab/recordings/`: ignored opt-in device recordings, never committed.
